# 0-7. 센서·계측·제어·데이터 — 장비가 스스로 맞추는 법

> 선행 학습: [0-2 진공](00-2-vacuum.md), [0-4 플라즈마](00-4-plasma-and-rf.md)
> 요지: 현대 장비는 "설정한 대로 돌아가는 기계"가 아니라 **"측정하면서 자기를 교정하는 기계"** 다. 그 차이를 만드는 것이 센서와 제어 루프다.

---

## 1. 제어의 3단 계층 — 어디까지 장비가, 어디부터 팹이

```
 ① 챔버 내 실시간 제어 (ms ~ s)          ─ 장비 내부
    압력(APC), 유량(MFC), 온도(PID), RF 매칭, 종점검출(EPD)
              │
 ② 웨이퍼/로트 단위 보정 (분 ~ 시간)     ─ 장비 + 팹 시스템
    R2R(Run-to-Run) 제어: 이전 결과 측정값으로 다음 레시피를 미세 보정
              │
 ③ 장비 상태 감시 (일 ~ 월)              ─ 팹 시스템
    FDC(고장 검출/분류), PdM(예지보전), SPC(공정 통계 관리), 챔버 매칭
```

이 3층을 구분하지 못하면 "센서가 많으면 좋은 거 아니야?" 수준에서 멈춥니다. 실제로는 **각 층에 맞는 신호가 따로 있습니다.**

## 2. 인시투(in-situ) 센서 도감 — 챔버 안에서 실시간으로 보는 것

| 센서 | 측정 원리 | 무엇을 아는가 | 한계 |
|------|-----------|---------------|------|
| **OES** (발광분광) | 플라즈마 발광 스펙트럼 | 종점 검출, 챔버 상태, 누설/오염, 챔버 매칭 | 윈도우 흐려짐, 개구율 작은 패턴에서 신호 약함 |
| **간섭계 IEP** (Interferometric Endpoint) | 웨이퍼 표면 반사광의 간섭 무늬 | **실시간 식각/증착 깊이**(두께) | 표면이 평탄·반사성 있어야 함, 패턴 의존 |
| **반사율 측정 (reflectometry)** | 특정 파장 반사율 | 막 두께, 표면 상태 변화 | 상동 |
| **RGA** (잔류가스분석) | 질량분석 | 누설/아웃개싱/부산물 조성 | 고압에서 사용 불가, 유지보수 |
| **VI 프로브** | 전극 전압·전류·위상 실측 | 실제 플라즈마 부하 상태, 아킹 | 캘리브레이션 |
| **매처 포지션 (C1/C2)** | 모터 인코더 | 챔버 내부 상태 변화(증착물·마모) | 간접 지표 |
| **He 백사이드 누설률** | 유량/압력 | 척킹 상태, 웨이퍼 휨, 유전체 마모 | — |
| **파이로미터** | 복사 | 웨이퍼 온도(RTP) | 방사율 의존 ([0-5장](00-5-thermal-and-chuck.md)) |
| **파티클 카운터 (in-line, 배기측)** | 광산란 | 챔버 파티클 이벤트 실시간 감지 | 웨이퍼 파티클과 1:1 아님 |
| **잔류 전류/전압 모니터 (임플란트 Faraday)** | 전류 적분 | **도즈** ([07장](07-ion-implantation.md)) | — |
| **레벨 센서 (노광)** | 간섭/공기압 | 웨이퍼 표면 높이 맵 → 포커스 보정 | — |
| **초음파/음향 (CMP)** | 모터 전류·마찰·에디전류 | CMP 종점 ([08장](08-cmp.md)) | — |

### 종점 검출(EPD)의 실제

식각에서 "언제 멈출지"는 시간으로만 정하면 위험합니다. 막 두께가 웨이퍼마다 다르고, 챔버 상태도 변합니다.

```
   [OES 기반 종점 검출 예 — 폴리 식각]

   발광강도
     │        ┌─────────────  (폴리 식각 중: SiF 등 부산물 발광 일정)
     │        │
     │        │      ╲        ← 폴리가 다 파여 산화막 노출
     │        │        ╲___   ← 부산물 발광 급감 = 종점
     └────────┴──────────────── 시간
                          ↑ 검출 후 "오버에치" 시간을 정해진 만큼만 추가
```

| 기법 | 원리 | 쓰는 곳 |
|------|------|---------|
| **시간 기반 (timed)** | 정해진 시간 | 두께 변동 작고 선택비 충분할 때 |
| **OES EPD** | 부산물/반응물 발광 변화 | 폴리/금속/컨택 식각 |
| **IEP (간섭)** | 두께 변화를 직접 봄 | 깊이 제어가 중요한 식각(리세스, 부분 식각) |
| **전류/전압 변화** | 부하 변화 | 일부 공정 |
| **모터 전류 / 에디 전류** | 마찰·금속 잔량 | CMP |

## 3. 인라인 계측(장비 밖) — 무엇을 어디서 재는가

자세한 장비 설명은 [10장 계측·검사](10-metrology-inspection-test.md). 여기서는 **제어 루프와의 관계**만 정리합니다.

| 측정 항목 | 대표 장비 | 어느 루프로 되돌아가나 |
|-----------|-----------|------------------------|
| 막 두께 | 엘립소미터, 반사계, XRF(금속), OCD | 증착/식각 시간, 온도, 유량 보정(R2R) |
| CD (선폭) | CD-SEM, OCD(스캐터로메트리) | 노광 도즈/포커스, 식각 바이어스 보정 |
| 오버레이 | 오버레이 계측기 | 스캐너 보정(그리드, 배율, 회전) — **R2R의 원조** |
| 결함/파티클 | 패턴/비패턴 검사기 | 장비 상태 판정(PM 트리거), 공정 이상 경보 |
| 저항/접촉저항 | 4점 탐침, 전기 테스트 | 임플란트 도즈, 금속/실리사이드 |
| 응력/휨 | 응력 측정기 | 증착 조건(응력 제어), 후속 공정 리스크 |
| 표면 거칠기/평탄도 | AFM, 웨이퍼 지오메트리 | CMP 조건 |

## 4. R2R (Run-to-Run) 제어 — 장비가 스스로 보정하는 구조

```
   레시피 ──▶ [장비] ──▶ 웨이퍼 ──▶ [계측] ──▶ 측정값
                 ▲                              │
                 │                              ▼
                 └──── 컨트롤러 (EWMA 등) ◀── 목표와의 편차
                      다음 로트 레시피를 조금 수정

   대표 예:
   · 노광 오버레이: 이전 로트 오버레이 측정 → 스캐너 보정 파라미터 갱신
   · 식각 시간: CD 측정값으로 식각 바이어스 보정
   · CMP 시간: 제거량 측정으로 다음 로트 시간 조정 (패드 마모 자동 보상)
```

| 구성 | 설명 |
|------|------|
| **필터(EWMA, Kalman)** | 측정 노이즈에 과반응하지 않게 지수가중 평균으로 완충. **게인이 크면 발진(oscillation)** |
| **컨텍스트 분리** | 장비·챔버·제품·레이어별로 별도 모델. 섞으면 엉뚱한 보정이 들어감 |
| **드리프트 vs 스텝** | 패드 마모 같은 완만한 드리프트는 R2R이 잘 잡지만, PM 직후 **스텝 변화**는 리셋이 필요 |
| **주의** | R2R은 **문제를 감추기도 합니다.** 부품이 마모돼 결과가 나빠지는데 R2R이 보정해 스펙 안에 두면, 근본 원인을 늦게 발견합니다 → 그래서 **보정량 자체를 모니터링**해야 합니다 |

## 5. FDC와 예지보전 — 고장을 결과보다 먼저 아는 법

**FDC(Fault Detection & Classification)**: 장비가 쏟아내는 트레이스 데이터(초당 수십~수백 개 변수)를 감시해 이상을 검출합니다.

| 단계 | 내용 |
|------|------|
| **데이터 수집** | Interface A / EDA 규격으로 트레이스 수집(압력, 유량, RF 순방향/반사, 매처 포지션, 온도, 밸브 개도, He 누설률…) |
| **요약 통계 생성** | 각 스텝 구간별 평균/표준편차/기울기/최대값 등 수백 개 지표(summary statistics) |
| **모델링** | 정상 구간 학습(단변량 한계선, 다변량 PCA/PLS, 최근에는 ML) |
| **검출/분류** | 이상 발생 시 알람 + 어떤 유형인지 분류 |
| **조치** | 자동 홀드(웨이퍼 손실 방지), 엔지니어 통지 |

### 좋은 FDC 지표의 특징 — "결과보다 먼저 움직이는 신호"

| 지표 | 무엇을 예고하나 |
|------|-----------------|
| **APC 밸브 개도 트렌드** | 배기 능력 저하(파우더/펌프 열화), 누설 |
| **RF 반사 파워 / 매처 포지션** | 챔버 내부 상태 변화, 부품 마모, 접지 불량 |
| **He 백사이드 누설률** | 척 유전체 마모, 웨이퍼 휨 |
| **가스 안정화 시간** | MFC 열화, 밸브 응답 |
| **OES 특정 라인 비율** | 챔버 내벽 상태, 누설, 부품 마모 |
| **펌프 전류/진동** | 파우더 퇴적, 베어링 |
| **RF hour / 웨이퍼 카운트 대비 드리프트 기울기** | 소모품 수명 도달 시점 예측(PdM) |

> **핵심 통찰**: 공정 결과(두께, CD)는 이미 웨이퍼를 만든 후에 나오는 **사후 지표**입니다.
> 장비 내부 신호는 **사전 지표**입니다. 현대 팹의 경쟁력은 "사전 지표로 얼마나 일찍 잡는가"에서 갈립니다.

## 6. 챔버 매칭 — 같은 레시피로 같은 결과 만들기

클러스터에 챔버가 4 ~ 6개 있고, 팹에 같은 모델 장비가 수십 대 있습니다. **전부 같아야** 합니다.

| 매칭 대상 | 방법 |
|-----------|------|
| **하드웨어** | 부품 리비전 통일, 소모품 수명 단계 맞춤, 갭/링 두께 실측 관리, 배관 길이·RF 케이블 동일화 |
| **센서 기준** | 게이지/MFC/온도 센서 캘리브레이션을 동일 표준으로 |
| **챔버 상태** | seasoning 조건 통일, 클린 레시피 통일 |
| **결과** | 동일 더미 웨이퍼로 두께/CD/균일도/파티클 비교 → 오프셋 테이블 생성 |
| **판정 기준** | 챔버 간 평균 차이(bias)와 산포(variance)를 모두 스펙화 |

> "PM3만 CD가 높다" 같은 문제는 대부분 **① 소모품 수명 위치가 다르다, ② 갭/링 실측값이 다르다, ③ 센서 캘 차이, ④ seasoning 이력 차이** 중 하나입니다.

## 7. SPC — 공정을 통계로 지키는 최소 지식

| 개념 | 의미 | 실무 포인트 |
|------|------|-------------|
| **관리도 (control chart)** | 시간에 따른 측정값과 관리한계(UCL/LCL) | 규격(spec)과 관리한계(control limit)는 **다른 것**. 관리한계는 공정 산포 기반 |
| **Cp / Cpk** | 공정 능력 지수 | Cpk는 중심 이탈까지 반영. 1.33 이상을 흔히 요구 |
| **트렌드/룰 위반** | 연속 상승, 한쪽 편향, 2σ 연속 등(Western Electric 룰) | 스펙 안이어도 **경향**이 보이면 조치 |
| **OOC / OOS** | Out of Control / Out of Spec | OOC는 "통계적으로 이상", OOS는 "규격 위반". OOC에서 잡는 것이 목표 |
| **게이지 R&R** | 측정 시스템 자체의 산포 | 측정 오차가 크면 관리도가 무의미. 문제 해결 전에 측정계를 먼저 검증 |

> 입문자 실수 1위: 측정기의 산포를 공정 산포로 착각하고 장비를 뜯는 것. **먼저 반복 측정으로 계측 재현성을 확인**하세요.

## 8. 디지털 트윈·AI 적용 현황 (개괄)

| 적용 | 내용 | 현실적 한계 |
|------|------|-------------|
| **가상 계측 (VM, Virtual Metrology)** | 장비 트레이스로부터 측정값을 예측해 **전수 계측 없이** 보정 | 모델 유지보수(드리프트), 신뢰 구간 관리 필요 |
| **예지보전 (PdM)** | 잔여 수명 예측으로 PM 시점 최적화 | 라벨(고장 사례) 부족, 부품 로트 변동 |
| **레시피 최적화 (DOE + ML)** | 실험 횟수를 줄여 최적점 탐색 | 물리 제약 반영이 필수 |
| **디지털 트윈** | 챔버 물리 모델 + 데이터 결합 | 플라즈마·표면반응 모델의 불확실성 |
| **이상 검출 자동화** | 다변량/딥러닝 | 오알람 비용이 큼(불필요한 홀드) |

> 냉정한 관점: AI가 잘 먹히는 영역은 **"측정 대체(VM)"와 "이상 조기 검출"** 입니다. "레시피를 AI가 자동 창작"하는 단계는 아직 제한적입니다. 물리 이해가 여전히 1순위입니다.

## 9. 트러블슈팅 — 센서/제어

| 증상 | 의심 | 확인 |
|------|------|------|
| 종점 검출 실패(미검출/오검출) | 윈도우 오염, 개구율 낮은 제품, 임계값 설정 | 윈도우 청소, 신호 대 노이즈 확인, 파장 재선정 |
| 계측값 산포가 갑자기 커짐 | **계측기 문제** 우선 의심 | 게이지 R&R, 동일 웨이퍼 반복 측정 |
| R2R 보정이 발진 | 게인 과다, 컨텍스트 혼입, 측정 지연 | 필터 파라미터, 컨텍스트 분리, 지연 보상 |
| FDC 오알람 폭주 | 모델 노후, 레시피 변경 미반영 | 모델 재학습, 스텝 정렬 확인 |
| 챔버 간 결과 차 | 매칭 항목 전반 | 갭/링 실측, 소모품 카운트, 센서 캘 |
| 스펙은 통과하는데 수율이 나쁨 | 계측 항목이 실패 모드를 못 보고 있음 | 측정 항목/위치 재설계, 결함 검사 추가 |
| 트레이스 데이터 유실 | 통신/수집 서버 | EDA 링크, 샘플링 레이트 |
